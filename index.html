Kolam

Kolam is the shared foundation for Gopinath's pet projects: Wake Me There, Forge Trainer, Zoorassic Park, FarmerFriend, the portfolio and whatever comes next. It is named after the dot-grid drawings at Tamil doorsteps: a fixed grid of dots, with endless patterns drawn around them. The tokens are the dots. Each app draws its own pattern.

Principles

  • Accessible by default, not by audit. If you use the tokens as their usage notes say, the result passes AA. Don't put a colour on a ground its note doesn't name.
  • One loud thing per screen. Ocean Azure (primary) marks the main action and the current location. Magenta Rose (accent) marks one highlight or notification. Deep Teal (secondary) supports both. Everything else is Ink Slate neutrals.
  • Phone first, thumb first. Controls are 44px tall (size-control-md), and every tap target is at least size-target-min.
  • Bilingual-ready. Every font stack falls back to Noto Sans Tamil. Text containers grow; nothing is clipped.

Content

  • Use sentence case everywhere: buttons, titles, tabs. Use uppercase only for caption overlines.
  • Address the person as "you". Write the app's voice as "we" ("We'll wake you 2 km before.").
  • Buttons start with a verb and name the outcome: "Set alarm", "Save plot", "Start set". Never "OK", "Submit" or "Yes".
  • Errors say what to do next: "Enter a distance between 0.5 and 20 km." Don't apologise.
  • Write numbers as digits with units: "8.4 km", "4 × 8", "06:40". Set aligned numbers in mono, or use font-variant-numeric: tabular-nums.
  • No emoji in the UI. Icons do that job.

Color

Every swatch below is live: switch the theme in the header and the colors, hex values and contrast ratios update.

Three themes: light (default), dark and contrast. Set data-theme on <html>. With no attribute, the theme follows prefers-color-scheme and prefers-contrast: more.

The brand hex values are kept exact. Where one misses 4.5:1 as text, a -text token carries a slightly darker shade of the same hue, and that shade is the one to use for words.

  • Grounds: bg (Ink Slate tint) is the page; surface holds content (cards, lists, inputs); surface-sunken is for wells and tracks; surface-raised is for dialogs and toasts. sidebar (Ink Slate) is for dark side panels and app bars, with on-sidebar text.
  • Text: ink (Ink Slate) for primary text, ink-2 for secondary text, ink-muted for placeholders and captions. All three pass 4.5:1 on all four grounds in every theme.
  • Lines: line is decorative only (dividers, card outlines). Control borders use line-strong, which passes 3:1 (WCAG 1.4.11).
  • Ocean Azure primary: primary buttons, selected states and progress fills, with on-primary text (4.87:1). For links and azure-coloured text, use primary-text.
  • Deep Teal secondary: the brand teal is for charts, icons and decorative marks (3:1). Secondary buttons are tonal: secondary-text on secondary-soft. When you need a solid teal button, use secondary-strong with on-secondary. Info states use the teal too (info and info-soft).
  • Magenta Rose accent: notification badges, counts and CTA highlights, with on-accent white text at exactly 4.5:1. For magenta words, use accent-text. Never use magenta for errors: those are danger (vermilion) with an icon.
  • Status: success, warning, danger and info are text and icon colours that pass on the surfaces and on their own -soft tint. Status always carries an icon and a word as well as colour (WCAG 1.4.1). Success is a blue-leaning green and danger is a vermilion, so the two also differ for people with red–green colour blindness.
  • Focus: a 2px solid focus ring, offset 2px, on every interactive element through :focus-visible. It passes 3:1 on all grounds in every theme (WCAG 2.4.7 and 2.4.13). Never remove it.

Per-project themes

Each app can override only the primary family: primary, primary-hover, on-primary, primary-soft and primary-text. Ocean Azure is the default; examples of overrides are Forge Trainer indigo or FarmerFriend field green. Keep everything else. A new primary must still pass 4.5:1 for on-primary on primary, 3:1 for primary on surface, and 4.5:1 for primary-text on every ground, in both light and dark. Check it before you ship.

  • Lato is Kolam's one typeface. It's free under the SIL Open Font License. display and sans both point to it.
  • Use three weights only: Regular (400) for reading, Bold (700) for headings, labels, buttons, badges and captions, and Black (900) for display-xl, display-lg and big stat numbers. Lato has no 500, 600 or 800, so don't ask for them.
  • Hierarchy comes from size and weight, not from a second font: display-xl and display-lg in Black, heading-1 to heading-3 in Bold, body text in Regular.
  • JetBrains Mono (mono) is for coordinates, codes and aligned figures.
  • Load Lato (400, 700, 900, and italic 400) and JetBrains Mono from Google Fonts. Each stack falls back to Noto Sans Tamil, then the system UI font.
  • Running text is body at 16px. Never go smaller for sentences. caption (12px) is the floor, and only for labels and timestamps.
  • Keep line length within size-measure (68ch). Headings use text-wrap: balance.
  • Tamil text gets more line height: :lang(ta) sets 1.7. Mark Tamil content with lang="ta".
  • Text must survive 200% zoom and the WCAG 1.4.12 text-spacing overrides. Use rem/em in your apps and never fix the height of a text container.

  • Spacing is on a 4px grid: space-1 (4) to space-16 (64). Use space-4 for phone gutters and card padding, space-6 between cards, and space-8 between sections.
  • Lay out groups with gap, not margins.
  • Radii: radius-sm for badges and checkboxes, radius-md for buttons and inputs, radius-lg for cards, radius-xl for dialogs and sheets, radius-pill for switches, segmented tabs and avatars.
  • Control heights: size-control-md (44px) is the default, size-control-lg (52px) is the phone CTA, and size-control-sm (32px) is for desktop toolbars only.

Elevation and motion

  • Separate surfaces with line first. Shadows are for floating things only: shadow-1 for resting cards, shadow-2 for menus and toasts, shadow-3 for dialogs. The contrast theme swaps shadows for solid outlines.
  • Durations: duration-fast (120ms) for hover and press, duration-base (200ms) for toggles, duration-slow (320ms) for sheets.
  • Every transition sits inside @media (prefers-reduced-motion: no-preference). Nothing flashes more than 3 times a second, and nothing auto-plays for more than 5 seconds without a pause control.

Iconography

  • Use Lucide icons (ISC licence): a 24px grid, 2px stroke, round caps and joins, currentColor. Use size-icon-md (20px) in controls and size-icon-lg (24px) in navigation.
  • Kolam has no brand icon set of its own. The component previews draw a few Lucide-style glyphs inline.
  • Decorative icons get aria-hidden="true". An icon-only control gets an aria-label. Icons that carry meaning must pass 3:1 against their ground.

Button

Triggers an action in place; use a link (<a>) when it navigates.

Markup: <button type="button" class="k-btn k-btn-primary">Set alarm</button>. Variants: k-btn-primary, k-btn-secondary, k-btn-ghost, k-btn-danger. Sizes: k-btn-sm (32px, desktop only), default (44px), k-btn-lg (52px phone CTA), plus k-btn-block for full width. An icon goes first, as <svg class="k-icon" aria-hidden="true">.

  • One primary per screen. It is the action the screen exists for. Everything else is secondary or ghost.
  • Labels start with a verb and use sentence case: "Set alarm", "Save plot". Avoid "OK" and "Submit".
  • Disabled: use disabled on a <button>, or aria-disabled="true" on a link. If the reason isn't obvious, tell people why nearby instead of leaving a dead button.
  • Loading: keep the width, swap the label ("Saving…") and add aria-busy="true".
  • k-btn-danger is only for the confirming step of a destructive action, usually inside a Dialog.
  • Never put an accent (marigold) fill on a button: it fails 3:1 against white surfaces.

IconButton

A 44×44 round button holding a single icon, for toolbars, close actions and app-bar actions.

Markup: <button class="k-iconbtn" aria-label="Search"><svg class="k-icon" aria-hidden="true">…</svg></button>. Add k-iconbtn-filled for the one emphasised action in a bar.

  • An aria-label is required. The icon is hidden from assistive tech, so the label is the only name.
  • Use it only when the icon is unmistakable (search, close, add, more). Otherwise use a Button with text.
  • The hit area stays 44px even when the drawn icon is 20px. Don't shrink it.

TextField

We'll wake you before you arrive.
Enter a distance between 0.5 and 20 km.

A labelled single-line or multi-line text input, with optional help and error text.

Markup: .k-field > label.k-label[for] + input.k-input[id] + .k-help / .k-error. Use <textarea class="k-input"> for multi-line text. To add a leading icon, wrap the input in .k-input-group.

  • Always have a visible <label>. A placeholder is a hint, not a label: it disappears when someone types.
  • Connect help and error text with aria-describedby. When the value is invalid, set aria-invalid="true". The 2px red border, the icon and the message all appear together, so the error never relies on colour alone.
  • Error text says what to do: "Enter a distance between 0.5 and 20 km", not "Invalid input".
  • Mark required fields with required and the visual asterisk (.k-req, aria-hidden). Mark optional fields with "(optional)" in the label instead.
  • Set inputmode and autocomplete (email, tel, postal-code) so phones show the right keyboard.
  • The font is 16px so iOS Safari doesn't zoom in when the field gets focus.

Select

A native dropdown for choosing one option from five or more.

Markup: .k-field > label.k-label[for] + select.k-select[id].

  • Keep the native <select>. It gives you the platform picker on phones and keyboard support for free.
  • With four or fewer options, use Radio or Tabs so every choice is visible.
  • The first option is a real, sensible default. Don't use a "Select…" placeholder unless an empty value is meaningful.

Checkbox

Remind me

Lets people turn independent options on or off. Changes take effect when the form is submitted.

Markup: label.k-check > input[type=checkbox] + span.k-check-box (containing the check SVG) + span.k-check-text (with optional <small>). Wrap a group in fieldset.k-fieldset with a <legend>.

  • The whole row is the label, so the tap target is at least 44px tall.
  • The native input is visually hidden but still focusable. Focus draws the ring on the box.
  • If a change should apply immediately (a setting), use Switch instead.

Radio

Wake me

Picks exactly one option from a short, visible list of two to five.

Markup: the same as Checkbox, with input[type=radio] sharing one name, inside fieldset.k-fieldset + <legend>.

  • Always preselect one option.
  • Arrow keys move between options. That comes free with native radios sharing a name.
  • For a compact switch between views, use Tabs instead.

Switch

An on/off setting that takes effect immediately.

Markup: label.k-switch > <span> label text + input[type=checkbox][role=switch] + span.k-switch-track.

  • Use it for settings that apply at once, with no Save button.
  • The label names the setting, not the state ("Vibrate", not "Vibrate on").
  • The on state differs by thumb position and fill, not colour alone.

Badge

A short, non-interactive label for status or category.

Markup: <span class="k-badge k-badge-success"><svg class="k-icon">…</svg>Harvested</span>. Tones: neutral (default), primary, accent, success, warning, danger, info. Add k-badge-pill for counts and "New".

  • One or two words. If it needs a sentence, use an Alert.
  • Status badges carry an icon and a word. Never use a coloured dot alone.
  • k-badge-accent (marigold) is for celebration and featured content, not warnings.

An inline banner for a message about the current screen.

Markup: div.k-alert[.k-alert-success|-warning|-danger] > icon + <div> (span.k-alert-title + span.k-alert-body). Info is the default.

  • Use role="status" for most alerts and role="alert" only for urgent errors, which interrupt screen readers.

Card

Push day

Bench press · 4 × 8

Last time 60 kg · rest 90 s

12day streak — your longest yet

Keep it going with a 20-minute session today.

A container that groups content and actions about one thing: a workout, a plot, an alarm, an animal.

Markup: article.k-card > optional .k-card-media, then h3.k-card-title, p.k-card-meta, actions. Use .k-card-featured (marigold tint) for one highlighted card. Use .k-stat (.k-stat-value + .k-stat-label) for a big number.

  • If the whole card is a link, make it an <a class="k-card"> with the title as its text, and put no other buttons inside.
  • Use one featured card per screen at most.
  • Don't nest cards. Inside a card, separate groups with spacing (space-3) or a line divider.
  • Lists of similar rows belong in a List, not a stack of cards.

Rows of similar items inside one bordered surface: alarms, crops, settings, search results.

Markup: ul.k-list > li > a.k-list-item (or button.k-list-item, or the li.k-list-item itself when not interactive). Each row has an optional leading icon, span.k-list-text (with <small>), and an optional trailing chevron or badge.

  • Rows are at least 56px tall and the whole row is the tap target.
  • Show a chevron only when the row navigates.
  • Keep the second line to one short fact. Truncate in your own code, not with clipping.

Tabs

A segmented control that switches between two to four views of the same content.

Markup: div.k-tabs[role=tablist][aria-label] > button.k-tab[role=tab][aria-selected]. Each panel gets role="tabpanel" and aria-labelledby.

  • Only the selected tab is in the tab order (tabindex="0"). Arrow keys move between tabs, as the preview script shows.
  • The selected tab is lifted on surface with a line-strong outline, so selection doesn't depend on colour alone.
  • Tabs switch views; they don't trigger actions. For app-level sections on a phone, use BottomNav.

BottomNav

Home Workouts Alerts Settings

The app-level navigation bar for phone PWAs, with three to five destinations.

Markup: nav.k-bottomnav[aria-label="Main"] > a > span.k-pip (icon) + label. Mark the current page with aria-current="page".

  • Every item has a visible text label. Icon-only navigation isn't allowed.
  • The current item gets a tinted pip and primary text, not colour alone.
  • Fix it to the bottom with position: fixed; bottom: 0. It already pads for env(safe-area-inset-bottom).
  • On wide screens, switch to a side rail or top navigation.

A determinate bar showing how far along something is.

Markup: .k-progress > .k-progress-head (label + value text) + .k-progress-track[role=progressbar] with aria-valuenow, aria-valuemin, aria-valuemax and aria-labelledby > .k-progress-fill with a width.

  • Always show the value as text too ("3 of 4", "8.4 km left"). The bar alone isn't enough.
  • Use aria-valuetext when the number means something specific (distance, time).

Toast

Alarm set for Tambaram

A brief, inverted confirmation of something the person just did.

Markup: div.k-toast[role=status] > icon + span.k-toast-text + optional button.k-btn.k-btn-ghost (Undo). Place it in a live region near the bottom, above the BottomNav.

  • Keep it under 6 words plus at most one action.
  • If it has an action, keep it on screen for at least 6 seconds and pause the timer on hover or focus (WCAG 2.2.1). Never auto-dismiss errors: use an Alert for those.
  • Toasts use the inverted pair (bg text on an ink fill), which keeps the same contrast ratio as the body text.

Dialog

Delete this plot?

Paddy · 2.5 acres and its 14 log entries will be removed. This can't be undone.

A modal that asks for a decision before the person continues.

Markup: a native <dialog class="k-dialog" aria-labelledby="t"> opened with showModal(), containing h2.k-dialog-title#t, p.k-dialog-body and .k-dialog-actions. The native element traps focus, closes on Esc and gets the ::backdrop scrim.

  • The title is the question ("Delete this plot?"). Buttons repeat the verb ("Delete plot" / "Keep plot"), never "Yes" and "No".
  • The confirming action goes last (on the right). Make it k-btn-danger when the action is destructive.
  • Return focus to the control that opened the dialog when it closes.
  • Use dialogs sparingly. Prefer undo (a Toast) over confirmation for reversible actions.

Avatar

G M AR

A round initial or photo representing a person.

Markup: span.k-avatar[role=img][aria-label="Name"] with one or two initials, or an <img alt="Name"> inside it. Sizes: default 40px, k-avatar-lg 56px. Use k-avatar-accent for the current user.

  • If the name is printed right next to the avatar, use aria-hidden="true" instead so it isn't read twice.

Accessibility checklist

  • 1.1.1 Every meaningful image has alt text; decorative images use alt="".
  • 1.3.1 Use real headings (h1–h3 in order), <label for>, <fieldset>/<legend>, lists and landmarks (header, nav, main).
  • 1.4.1 Colour is never the only signal. Pair it with an icon, a word, a shape or a position.
  • 1.4.3 / 1.4.11 Use only the token pairs named in usage notes: 4.5:1 for text, 3:1 for UI and graphics.
  • 1.4.4 / 1.4.10 The layout works at 200% zoom and at 320px wide with no sideways scrolling.
  • 2.1.1 Everything works with a keyboard. Use native <button>, <a>, <input> and <dialog> before building your own.
  • 2.4.3 / 2.4.7 Focus order follows the visual order, and the focus ring is always visible.
  • 2.5.8 Targets are at least 24px. Kolam uses 44px.
  • 3.3.1 / 3.3.2 Fields have visible labels; errors are announced (aria-invalid + aria-describedby) and explain the fix.
  • 4.1.2 Custom widgets carry a role, a name and a state: role="switch", aria-selected, aria-current, aria-expanded.

Use it in a project

  • Web (HTML/CSS PWAs): copy tokens.css and kolam.css into the project and link them in that order. Then use the k- classes from the component previews. Style your own components through the CSS variables only, never through raw hex values.
  • iOS (SwiftUI): use Kolam.swift. It holds the same colour tokens as dynamic light/dark colours, plus spacing and radius constants. Point the project's AccentColor asset at primary so the two never drift apart.
  • When a project needs a new colour, add a token here first, with a usage note and a contrast check, then use it in the project.
